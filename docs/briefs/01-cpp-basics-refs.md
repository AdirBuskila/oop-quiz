# הפניות, ערכי ברירת מחדל והעמסת פונקציות

> 🔑 **בשורה אחת:** הפניה (`int&`) היא שם נוסף לאותו משתנה: חייבים לאתחל אותה בהצהרה, אי אפשר להפנות אותה מחדש, ופונקציה שמחזירה הפניה אפשר לשים בצד שמאל של השמה. בהעמסה מחליטים לפי **הפרמטרים בלבד**, לא לפי טיפוס ההחזרה.

## מה המבחן שואל

- "אילו שורות לא מתקמפלות": `int &r;` בלי אתחול (18A-A שאלה 1, 18A-B שאלה 19).
- "מה מדפיסה התכנית" עם ערכי ברירת מחדל: `f(3)` כש-`f(int x=4, int y=5)` מדפיסה `35` (18A-A שאלה 2).
- מה צריך להיות טיפוס ההחזרה כדי ש-`f() = 5;` יתקמפל: `int&` (18A-B שאלה 1, 19A-C שאלה 17).
- העברה לפי ערך, לפי הפניה ולפי מצביע: האם `x.f` השתנה (18A-B שאלה 2, 18A-C שאלה 2).
- העמסה ועמימות: שתי פונקציות `funC(int i=10)` ו-`funC()` ואז הקריאה `funC()` (19A-A שאלה 3, 19A-B שאלה 2); `f(int,double)` מול `f(double,int)` עם `f(1,2)` (19A-B שאלה 3); בחירת ארגומנטים כך שיודפס 2 או 7 (20B-A שאלות 7 ו-12); כמה שורות שגויות בקבוצת העמסות (23B-B שאלה 1).
- האם אפשר להעמיס לפי טיפוס ההחזרה: לא (`25S-A-Q17`, 20B-A שאלה 6).
- הפניה שמוחזרת מפונקציה עם משתנה `static` בפנים (19A-A שאלה 4, 21B-B שאלות 6 ו-7), `smallest(k,m) = 10` (23S-A שאלה 1), הפניה למערך (23S-A שאלה 10).
- `struct` ב-C++: שדות ציבוריים כברירת מחדל, יכול להכיל פונקציות, ואין צורך לכתוב `struct` בהכרזת משתנה (23B-B שאלה 14).

## הגדרות

- **הפניה** `T& r = x;` היא כינוי ל-`x`. חייבת אתחול בהצהרה, תמיד קשורה לאותו אובייקט, אין "הפניה ריקה". `r = 7` משנה את `x`.
- **העברת פרמטר:** לפי ערך (העתק, השינוי לא חוזר), לפי הפניה `T&` (אותו אובייקט), לפי מצביע `T*` (צריך לשלוח `&x`, ובתוך הפונקציה `p->f`).
- **ערך ברירת מחדל** חל על הפרמטרים הימניים בלבד, ונכתב פעם אחת (בהצהרה). כשחסר ארגומנט משלימים מימין.
- **העמסה** (overloading): אותו שם, רשימת פרמטרים שונה (מספר או טיפוסים). טיפוס ההחזרה לא נחשב.
- **משתנה static מקומי** מאותחל פעם אחת, בקריאה הראשונה, וחי עד סוף התכנית.
- **struct מול class:** ההבדל היחיד הוא ברירת המחדל לגישה (`struct` ציבורי, `class` פרטי). לשניהם פונקציות, בנאים וירושה.

## מתכונים

**אילו שורות לא מתקמפלות.** עוברים שורה שורה: הפניה בלי אתחול, השמה ל-`const`, קריאה בלי פונקציה מתאימה, קריאה עמומה.

**בחירת העמסה.**
1. מסננים את הפונקציות שאפשר לקרוא להן במספר הארגומנטים (עם ערכי ברירת המחדל).
2. לכל ארגומנט בודקים מי מתאימה בדיוק, מי דורשת המרה.
3. פונקציה "מנצחת" רק אם היא לפחות טובה כמו כל השאר בכל ארגומנט ובאחד טובה יותר. אם אין כזו, יש **עמימות** ושגיאת קומפילציה.

**מה מדפיסה התכנית עם הפניות.** מציירים קופסה לכל משתנה ושם לכל הפניה. הפניה לא יוצרת קופסה חדשה. פרמטר לפי ערך הוא קופסה חדשה עם עותק.

## דוגמה

```cpp
#include <iostream>
using namespace std;

void f(int x = 4, int y = 5) { cout << x << y << "\n"; }
int& g(int& x, int y) { x = --y; return x; }
int main() {
    f();
    f(3);
    f(1, 2);
    int x = 4;
    cout << g(x, x)++;     // y is a copy of 4, so x becomes 3; ++ acts on x itself
    cout << ++x << "\n";
}
```

```text
45
35
12
35
```

`f()` מדפיסה `45`, `f(3)` נותנת `35`, `f(1,2)` נותנת `12`. ב-`g(x, x)` הפרמטר `y` הוא עותק של 4. `--y` נותן 3, ו-`x` (הפניה למשתנה של `main`) הופך ל-3. `g` מחזירה הפניה ל-`x`, לכן `++` מעלה את `x` ל-4, אבל מודפס הערך שהיה לפני ההגדלה: `3`. אחר כך `++x` נותן `5`. סך הכול `35`.

תוכנית נוספת, עם משתנה static שמוחזר בהפניה:

```cpp
#include <iostream>
using namespace std;

int& counter() {
    static int c = 0;      // initialized once, lives until the program ends
    return ++c;            // returns an alias to c, not a copy
}
int main() {
    int x = 5;
    int& r = x;            // r is another name for x
    r = 7;
    cout << x << "\n";     // x changed through r
    counter() = 10;        // legal: counter() is an lvalue
    cout << counter() << "\n";
}
```

```text
7
11
```

העברה לפי ערך, הפניה ומצביע:

```cpp
#include <iostream>
using namespace std;

struct X { int f; };
void byValue(X x) { x.f = 5; }
void byRef(X& x) { x.f = 6; }
void byPtr(X* x) { x->f = 7; }
int main() {
    X x; x.f = 3;
    byValue(x); cout << x.f;
    byRef(x);   cout << x.f;
    byPtr(&x);  cout << x.f << "\n";
}
```

```text
367
```

## מלכודות

> 🪤 **קריאה עמומה עם ערכי ברירת מחדל.** כש-`funC(int i=10)` ו-`funC()` קיימות יחד, `funC(8)` תקינה אבל `funC()` עמומה. הקומפיילר מדווח:

```text
L2: call to 'funC' is ambiguous
```

> 🪤 **עמימות בין שתי המרות.** `p(int,double)` ו-`p(double,int)` נותנות התאמה מדויקת רק לקריאות `p(1,2.5)` ו-`p(1.5,2)`. הקריאה `p(1,2)` צריכה המרה אחת בכל אפשרות ולכן עמומה:

```text
L1: call to 'p' is ambiguous
```

ובקריאות שאינן עמומות, כל אחת בוחרת את ההעמסה המדויקת (וגם הפרדה בין `a(int&,char)` ל-`a(char,int)`):

```cpp
#include <iostream>
using namespace std;

int a(char c, int i) { return i++; }
int& a(int& i, char c) { return ++i; }
void p(int i, double j) { cout << "id "; }
void p(double i, int j) { cout << "di "; }
int main() {
    int x = 4;
    cout << a(x, 'x') << a('x', x) << "\n";
    p(1, 2.5);                 // exact match for (int,double)
    p(1.5, 2);                 // exact match for (double,int)
    cout << "\n";
}
```

```text
55
id di 
```

> ⚠️ **אותה פונקציה נקראת שוב.** ב-`smallest(k,m) = 10;` ואחר כך `smallest(k,m)--;` הבחירה נעשית מחדש בכל קריאה, לפי הערכים באותו רגע (23S-A שאלה 1: `k=5, m=10`).

> ⚠️ **`x++` על תוצאת פונקציה.** אם הפונקציה מחזירה הפניה, ה-`++` משנה את המשתנה המקורי. אם מחזירה ערך, אי אפשר להשים לתוצאה.

> ⚠️ **אי אפשר לקשור `int&` לערך זמני:** הקריאה `f1(2,3)` לפונקציה שמקבלת `int&` לא מתקמפלת (21B-B שאלה 6).
